# Security

This is an alpha local bridge. Do not expose its queue directory to other users or the internet. The CLI has no authentication of its own: only a trusted local execution path should invoke it. Treat its JSON replies as untrusted content. Keep credentials, private transcripts, and sensitive prompts out of the queue. Known token patterns are redacted heuristically, but arbitrary secrets may still appear.

The default Claude adapter is conversation-only. One bounded, two-turn no-tools smoke test passed on Windows; this does not establish broader provider or platform compatibility. It disables tools and unattended permission prompts.

The opt-in patch adapter uses the same no-tools Claude invocation. It sends explicitly selected tracked text files to Claude as prompt context; do not select files containing secrets. The model's reply is untrusted data. Only a restricted, reviewed unified diff can be applied, by a separate local CLI action with an exact digest. No advisory hook is treated as a write gate. A local caller with access to the private queue and `patch-apply` can approve changes; secure the upstream execution path. A local process able to race or replace worktree files is outside the bridge's threat model. This is not an OS sandbox.

Patch mode requires a clean separate worktree, named branch, pinned HEAD, selected regular tracked files, and rejects symlinks and hard links for those files. Bridge Git calls suppress executable filesystem monitors and inherited Git configuration, reject executable local filters and diff drivers, and refuse Git attributes on selected files. Diff validation and `git apply --check --index` precede application. The bridge computes expected bytes in disposable copies and verifies staged and working bytes after applying. If a crash or unexpected transformation occurs after Git writes, the worktree must be inspected manually; no automatic replay occurs. The patch workflow is offline tested but has not had a live coding-model call. Never point it at the running Backpacker worktree or an unrelated Claude session.

The opt-in channel uses Claude Code's research-preview MCP channel protocol. It does not inject into a foreground session that was started without channel opt-in. A registered target is bound to its discovered UUID, Git root, and PID; this is identity within the trusted local OS account, not protection from another same-user process. Source labels come from the authenticated upstream caller and cannot themselves authenticate a sender. The MCP server has a reply tool but deliberately declares no permission relay capability. An inbound message or model reply cannot approve a Claude tool action. A channel notification write is only `emitted`; the queue reports `completed` only after a matching reply-tool call. Restart or loss after dispatch is `unknown`, and no automatic resend occurs. The private queue holds prompt and reply text, so protect the directory and backups. The channel's Node integration is fixture tested; live delivery into a resumed Claude session is unverified.

For a vulnerability, use GitHub's private vulnerability reporting if it is available for this repository. Otherwise, open a minimally descriptive issue requesting a private reporting channel; do not post exploit details or secrets publicly. No private contact address is provided by this project.
